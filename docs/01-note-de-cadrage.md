Objectif 1 : Corriger les bugs plus vite   
    - Pratique : Automatiser avec le CI/CD.   
    - Métrique : Le lead time (le temps que ça prend entre le code et la mise en prod).   
    - Risque : Perdre énormément de temps à tout faire à la main et être trop lent. 
      
Objectif 2 : Garder l'application toujours disponible   
    - Pratique : Automatiser les déploiements pour que ce soit toujours identique.   
    - Métrique : Le MTTR (le temps qu'on met pour réparer un incident).   
    - Risque : Que l'application plante souvent en production à cause d'erreurs humaines.   

Objectif 3 : Protéger les données de l'application   
    - Pratique : Le Shift Left (penser à la sécurité dès le début du développement).  
    - Métrique : Le nombre de failles de sécurité qu'on a corrigées.  
    - Risque : Découvrir une énorme faille à la fin du projet qui bloque toute la sortie
